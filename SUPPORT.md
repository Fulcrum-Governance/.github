# Support

Where to get help, by topic.

## I have a question or feature request

Open an issue on the **specific repo** the question relates to:

- **Boundary: proxy, adapters, policies, records, the Lean sources in docs/proofs/** → [Fulcrum-Boundary/issues](https://github.com/Fulcrum-Governance/Fulcrum-Boundary/issues)
- **Hosted control plane, trust engine, proof work** → private during build; email `agent@fulcrumlayer.io`.

Architecture questions: [Fulcrum-Boundary Discussions](https://github.com/Fulcrum-Governance/Fulcrum-Boundary/discussions).

## Email — single address, subject-line routing

All non-issue inquiries go to **`agent@fulcrumlayer.io`**. Use a subject-line prefix so the right thread gets prioritized:

| Topic | Subject prefix | Notes |
|-------|---------------|-------|
| Security vulnerability | `[security]` | See [SECURITY.md](./SECURITY.md). Do **not** open a public issue. |
| Commercial / BSL licensing | `[licensing]` | `fulcrum-io` ships under BSL 1.1 with a 2030-05-04 conversion to Apache 2.0. The Additional Use Grant permits production use within your organization but excludes hosted-competing-service use. Contact us if your use case sits outside that grant. |
| Lean proof collaboration / peer review | `[research]` | For proof collaboration or peer review on the Lean sources in Fulcrum-Boundary docs/proofs/. Use a Boundary issue with the `research-question` label if it's a public conversation. |
| Partnership, design-partner program, pilot | `[partnership]` | Tell us your stack, the agent surface you'd govern, and the timeline. |
| Code of Conduct report | `[conduct]` | See [CODE_OF_CONDUCT.md](./CODE_OF_CONDUCT.md). |

We respond on best-effort, with security reports prioritized per [SECURITY.md](./SECURITY.md)'s 5-business-day acknowledgement window.
